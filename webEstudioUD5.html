01 · ¿Qué es el DOM?

El DOM es el árbol de objetos que representa tu HTML. JavaScript utiliza document para encontrar elementos, leerlos y modificarlos.

<main id="app">
  <h1>Inventario RPG</h1>
  <section id="inventario">
    <article class="objeto">
      <h2>Espada</h2>
      <button>Equipar</button>
    </article>
  </section>
</main>
document
└── main#app
    ├── h1
    └── section#inventario
        └── article.objeto
            ├── h2
            └── button
PropiedadPara qué sirve
parentElementAccede al elemento padre
childrenHTMLCollection viva de elementos hijos directos
childNodesNodeList de nodos hijos, incluidos textos
firstElementChildPrimer elemento hijo
nextElementSiblingSiguiente hermano que es un elemento
Para contar elementos hijos, normalmente utiliza elemento.children.length. Los saltos de línea y espacios pueden generar nodos de texto, que childNodes sí incluye.

02 · Seleccionar elementos HTML

querySelector()

Busca el primer elemento que coincida con un selector CSS. Recibe un selector (string); devuelve un elemento o null.

document.querySelector("#inventario");       // Por ID
document.querySelector(".tarjeta");          // Por clase
document.querySelector("button");            // Por etiqueta
document.querySelector("[data-id]");         // Con atributo
document.querySelector('[data-id="3"]');     // Atributo y valor

querySelectorAll()

Busca todas las coincidencias y devuelve una NodeList estática.

const tarjetas = document.querySelectorAll(".tarjeta");
for (const tarjeta of tarjetas) {
  console.log(tarjeta.textContent);
}
Diferencia: querySelector() devuelve uno (o null); querySelectorAll() devuelve una colección. También puedes buscar dentro de un elemento: columna.querySelector(".lista").

03 · closest(): buscar hacia arriba

closest(selector) comprueba el propio elemento y sube por sus antepasados hasta encontrar una coincidencia. Devuelve un elemento o null.

<article class="tarjeta" data-id="7">
  <h3>Estudiar JavaScript</h3>
  <button data-accion="empezar">Empezar</button>
</article>

const boton = document.querySelector("button");
const tarjeta = boton.closest(".tarjeta");
button (punto de partida)
   │
   └── closest(".tarjeta")
                │
                ▼
         article.tarjeta
querySelector busca hacia abajo (descendientes); closest busca hacia arriba (él mismo y antepasados).

06 · Crear elementos dinámicamente

document.createElement(etiqueta) crea un elemento en memoria; no aparece en la página hasta que lo insertas.

const titulo = document.createElement("h3");
titulo.textContent = "Estudiar JavaScript";

article.append(titulo);

const lista = document.querySelector(".lista");

07 · append() y replaceChildren()

MétodoQué hace
append(nodo)Añade al final; conserva los nodos anteriores
replaceChildren()Vacía todos los hijos
replaceChildren(a, b)Sustituye todos los hijos por a y b
remove()Elimina el elemento del DOM
// Si repintas tres veces con append sin limpiar:
// [Espada] [Poción] [Espada] [Poción] ...

lista.replaceChildren(); // Limpiar
for (const elemento of nuevosElementos) {
  lista.append(elemento);
}

// Alternativa: un array de nodos
lista.replaceChildren(...nuevosElementos);
Los tres puntos (...) expanden los elementos del array para pasarlos como argumentos independientes.

08 · Renderizar arrays

Renderizar es dibujar en HTML lo que contiene el modelo de datos.

const tareas = [
  { id: 1, titulo: "Estudiar JavaScript" },
  { id: 2, titulo: "Practicar Python" },
];

function pintarTareas() {
  const lista = document.querySelector("#lista");
  lista.replaceChildren();

  for (const tarea of tareas) {
    const article = document.createElement("article");
    article.classList.add("tarjeta");
    article.dataset.id = tarea.id;

    const h3 = document.createElement("h3");
    h3.textContent = tarea.titulo;

    article.append(h3);
    lista.append(article);
  }
}

Si modificas el array, la página no cambia sola:

tareas.push({ id: 3, titulo: "Preparar examen" });
pintarTareas(); // Ahora sí se actualiza el HTML

         │
         ▼
       render()
         │
         ▼
      PÁGINA HTML

10 · event.target vs event.currentTarget

<button id="comprar">
  <span>Comprar</span>
</button>

boton.addEventListener("click", (evento) => {
  console.log(evento.target);
  console.log(evento.currentTarget);
});
button#comprar ← currentTarget: quién escucha
     └── span  ← target: dónde ocurrió el clic

Si pulsas sobre el texto del span, evento.target puede ser el span, no el botón. Por eso en delegación usamos closest() para localizar el botón.

11 · Propagación y delegación

Los clics normalmente burbujean: viajan desde el objetivo hacia sus antepasados. Podemos escuchar muchos botones desde un solo contenedor.

#columnas ← aquí ponemos un listener
   ▲
 .lista
   ▲
.tarjeta
   ▲
 button ← aquí pulsa el usuario
const inventario = document.querySelector("#inventario");

inventario.addEventListener("click", (evento) => {
  const boton = evento.target.closest("button[data-accion]");
  if (!boton) return;
  console.log(boton.dataset.accion);
});
Un único listener en el contenedor sirve también para botones creados después. En Kanban es esencial, porque las tarjetas se reconstruyen al repintar.

12 · La función delegar() de B3

export function delegar(contenedor, tipo, selector, manejador) {
  const funcion = (evento) => {
    const elemento = evento.target.closest(selector);
    if (!elemento) return;

    if (contenedor.contains(elemento)) {
      manejador(elemento, evento);
    }
  };

  contenedor.addEventListener(tipo, funcion);

  return () => {
    contenedor.removeEventListener(tipo, funcion);
  };
}
ParámetroDescripción
contenedorElemento padre que escuchará
tipoEvento, por ejemplo "click"
selectorQué elementos interesan
manejadorFunción que recibe el elemento encontrado y el evento

Devuelve una función para quitar el listener:

const quitar = delegar(inventario, "click", "button[data-accion]", (boton) => {
  console.log(boton.dataset.accion);
});
// ...más tarde:
quitar();

contains() verifica que el elemento encontrado sigue dentro del contenedor; removeEventListener() necesita la misma referencia a la función registrada.

13 · B4: pintar() en el Kanban

La misión de pintar() es dejar la página exactamente igual que el modelo: pintar tareas ordenadas, generar botones, actualizar contadores y mostrar el resumen.

pintar()
   ├── Recorrer [data-columna]
   │      ├── Obtener nombre con dataset.columna
   │      ├── Consultar tablero.columna(nombre)
   │      ├── Obtener ordenadas()
   │      ├── pintarLista(lista, tareas, ahora)
   │      ├── Crear botones en cada .tarjeta
   │      └── Actualizar .contador
   └── tablero.resumen(ahora)
          ├── Calcular % progreso
          └── Mostrar vencidas

El elemento HTML no es el objeto del modelo

const columna = document.querySelector('[data-columna="En curso"]');
// columna → elemento HTML

const columnaTablero = tablero.columna("En curso");
// columnaTablero → objeto Columna del modelo

const tareasOrdenadas = columnaTablero.ordenadas();
// tareasOrdenadas → array de tareas

Contador y progreso

contador.textContent = `(${tareasOrdenadas.length})`;

const progreso = total === 0
  ? 0
  : Math.round((hechas / total) * 100);
B4 no registra listeners. Repintar cambia nodos, y los listeners de la página deben configurarse una sola vez en iniciarApp().

14 · B5: acciones y avisos

Los botones creados por B4 tienen que hacer algo. B5 escucha el clic, identifica la acción y el ID, modifica el tablero y luego vuelve a pintar.

CLIC EN «EMPEZAR»
       │
       ▼
     delegar()
       │
       ├── boton.dataset.accion → "empezar"
       └── boton.closest(".tarjeta").dataset.id → "3" → 3
       │
       ▼
 tablero.mover(3, "En curso")
       │
       ├── Éxito → avisar("") → pintar() → alCambiar(tablero)
       │
       └── ErrorTablero → avisar(error.message)
delegar(columnas, "click", "button[data-accion]", (boton) => {
  const accion = boton.dataset.accion;
  const tarjeta = boton.closest(".tarjeta");
  const id = Number(tarjeta.dataset.id);

  try {
    if (accion === "empezar") {
      tablero.mover(id, "En curso");
    } else if (accion === "volver") {
      tablero.mover(id, "Por hacer");
    } else if (accion === "completar") {
      tablero.completar(id);
    }

    avisar("");
    pintar();
    alCambiar(tablero);
  } catch (error) {
    if (error instanceof ErrorTablero) {
      avisar(error.message);
    } else {
      throw error;
    }
  }
});
Este código corresponde al manejador de B5 que has estudiado. Se coloca una sola vez dentro de iniciarApp(), nunca dentro de pintar().

15 · try/catch e instanceof

try {
  tablero.mover(id, "En curso");
  avisar("");
  pintar();
} catch (error) {
  if (error instanceof ErrorTablero) {
    avisar(error.message);
  } else {
    throw error;
  }
}

Si tablero.mover() lanza una excepción, JavaScript salta al catch y no ejecuta pintar() en ese recorrido.

SituaciónAcción
Operación correctaOcultar aviso, pintar, avisar del cambio
ErrorTablero o subclasesMostrar error.message y no repintar
Otro error inesperadothrow error, para no esconder un fallo de programación

instanceof ErrorTablero también reconoce sus subclases, como ColumnaLlenaError.

16 · B6: submit, preventDefault y FormData

const form = document.querySelector("#form-alta");

form.addEventListener("submit", (evento) => {
  evento.preventDefault();
  console.log("Formulario enviado sin navegación predeterminada");
});

submit escucha el envío del formulario, incluso al pulsar Enter; preventDefault() evita su comportamiento normal.

Leer valores con FormData

<form id="registro">
  <input name="usuario" value="Steve">
  <input name="nivel" type="number" value="10">
</form>

const datos = Object.fromEntries(new FormData(form));
// { usuario: "Steve", nivel: "10" }

datos.nivel = Number(datos.nivel);
HerramientaQué devuelve/hace
new FormData(form)FormData con controles del formulario que participan en el envío
Object.fromEntries(...)Objeto a partir de pares clave-valor (ojo con nombres repetidos)
form.elementsColección de controles del formulario
form.reset()Restablece valores iniciales
Para que FormData recoja un campo, este necesita el atributo name. Los campos numéricos comunes llegan como texto, así que conviértelos cuando corresponda.

17 · Validar y mostrar errores

En B6, validar(datos) no toca el DOM: devuelve {} si todo está bien o un objeto como { titulo: "Obligatorio" } si hay errores.

const errores = validar(datos);
mostrarErrores(form, errores);

if (Object.keys(errores).length > 0) {
  return; // No crear nada si hay errores
}

// Si es válido, crear tarea desde el modelo...

mostrarErrores() debe llamarse tanto cuando hay errores como cuando no, para limpiar los mensajes anteriores.

Herramientas útiles

Number.isInteger(datos.cadaDias);  // Comprueba entero
form.elements["titulo"];          // Control cuyo name es titulo
campo.setAttribute("aria-invalid", "true");
campo.removeAttribute("aria-invalid");
form.reset();
El navegador también ofrece required, min, max, pattern, checkValidity(), validity y setCustomValidity(). La validación del cliente ayuda al usuario, pero el servidor debe validar de nuevo.

18 · La regla de oro: EVENTO → MODELO → RENDER()

ANTES
Modelo: tarea 3 en "Por hacer"
HTML:   tarea 3 en "Por hacer"

1. EVENTO
   El usuario pulsa "Empezar".

2. MODELO
   tablero.mover(3, "En curso");

3. RENDER
   pintar();

DESPUÉS
Modelo: tarea 3 en "En curso"
HTML:   tarea 3 en "En curso"

No muevas tarjetas manualmente en el DOM si el estado real pertenece al tablero. Cambia el modelo y repinta desde él.

Si entiendes qué parte lee el HTML, cuál cambia las clases del modelo y cuál actualiza la pantalla, estarás preparado para funciones largas como pintar() y manejadores como B5.

Autoevaluación 1 · ¿Qué devuelve dataset.id?

Un texto (string). Si necesitas un número, utiliza Number(...).

Autoevaluación 2 · ¿Por qué el listener está en #columnas?

Porque el contenedor se conserva cuando repintas; las tarjetas y sus botones se reconstruyen. La delegación funciona con los nuevos botones.

Autoevaluación 3 · ¿Qué ocurre si tablero.mover() lanza ErrorTablero?

Se salta al catch; se muestra el aviso y no se ejecutan las instrucciones posteriores del try, como pintar().

Autoevaluación 4 · ¿Por qué no basta con modificar solo el HTML?

Porque el modelo seguiría teniendo los datos anteriores y el siguiente renderizado podría restaurarlos. Debes seguir evento → modelo → render.

Para el examen, no memorices únicamente B4 o B5: aprende a explicar qué recibe cada función, qué devuelve, de dónde sale cada dato y qué cambia después de ejecutarla.
